# Reprokit 法人向けセキュリティ研修機能要件

> **ステータス：方針整理（2026-10-17）**  
> 本書は、Reprokitを個人向け学習ツールではなく、法人向けの開発者セキュリティ研修基盤として再定義した時点の機能要件をまとめる。既存文書に残る個人・初学者向けの記述は、今後この方針に合わせて更新する。

## 1. プロダクトの位置付け

Reprokitは、**実際に運用されていたプロダクトで報告された脆弱性を、安全な再現環境で追体験し、原因・修正・再発防止まで学ぶための法人向け開発者研修基盤**である。

CVE IDそのものを学習の入口にはしない。教材では「実際に何が起きたか」「なぜ起きたか」「どう直されたか」を中心に扱い、CVE ID、ベンダーアドバイザリ、修正コミットなどは、実在事例であることを示す根拠情報として提示する。

Vulhubおよび互換Labは脆弱環境の供給元として利用する。Reprokitの主な提供価値は、Vulhubを起動することではなく、次の要素を一つの研修体験として提供することにある。

- 実在事例に基づく教材
- 安全性を検査した再現環境
- 再現から原因、修正、再発防止までの学習導線
- 受講者の理解を確認する課題
- 法人研修としての割り当て、進捗確認、監査

### 一言で説明すると

**実在した脆弱性を追体験し、原因と修正を説明できる開発者を育てる。**

## 2. 対象顧客と利用者

### 2.1 初期の対象顧客

専任のAppSec担当者や研修教材を十分に持たず、新人・若手開発者へセキュア開発教育を行いたいWeb開発企業を初期対象とする。

### 2.2 利用者の役割

| 役割 | 主な責務 |
| --- | --- |
| 組織管理者 | 組織、ユーザー、認証、権限、利用設定を管理する |
| 研修担当者 | コースを選択し、対象者、受講期限、完了条件を設定する |
| 教材作成者 | LessonとLabを作成・編集する |
| セキュリティレビュー担当 | 教材の正確性、出典、Labの安全性を確認し、公開を承認する |
| 受講者 | 教材を読み、Labを操作し、確認課題へ回答する |
| 上長・監査担当 | 受講状況、完了状況、理解度を確認する |

### 2.3 受講者の前提

- Webアプリケーションの開発経験がある
- HTTP、CLI、Gitなどの基礎を理解している
- 脆弱性の再現、原因分析、修正を実務で経験していない
- セキュリティ専門職ではなく、主にアプリケーション開発者である

## 3. 解決する課題

- 全社員向け情報セキュリティ研修だけでは、安全な実装方法を学べない
- 座学では知識が実装やコードレビューに結び付かない
- CTFでは攻略が中心になり、業務上の原因分析や再発防止につながりにくい
- 脆弱環境の準備、安全性確認、後片付けに研修担当者の負担がかかる
- 実在事例を研修教材に変換するための調査と教材設計に専門知識が必要になる
- 受講完了だけでは、受講者が原因と修正方法を理解したか判断できない

## 4. 優先度の定義

| 優先度 | 意味 |
| --- | --- |
| P0 | 研修MVPの成立に必須 |
| P1 | 法人での継続利用・運用に必要 |
| P2 | 将来構想。MVPの完成条件には含めない |

## 5. 機能要件

### 5.1 教材・学習体験

| ID | 要件 | 優先度 |
| --- | --- | --- |
| EDU-01 | 実在プロダクトで発生した脆弱性を、業務に近いシナリオとして表示する | P0 |
| EDU-02 | 学習目標、対象者、前提知識、想定所要時間を表示する | P0 |
| EDU-03 | 「発生背景 → 再現 → 観察 → 原因 → 修正 → 再発防止」の順で学習できる | P0 |
| EDU-04 | 操作手順、期待結果、観察ポイント、段階的なヒントを表示する | P0 |
| EDU-05 | 脆弱版と修正版の挙動、コード、設定の差を比較できる | P0 |
| EDU-06 | 受講者が原因、影響、修正方針、再発防止策を文章で回答できる | P0 |
| EDU-07 | 回答例または評価基準を研修担当者へ提供する | P0 |
| EDU-08 | クイズや確認課題により理解度を判定する | P1 |
| EDU-09 | 難易度、技術領域、脆弱性分類、前提知識から教材を検索できる | P1 |
| EDU-10 | 複数Lessonを一つの研修コースとして編成できる | P1 |

教材の表示名では、原則としてCVE IDよりも現象と学習内容を優先する。

例：`CVE-2021-41773`ではなく、`URLの正規化不備により非公開ファイルを読み取られる`と表示する。CVE IDや原典は教材詳細の根拠情報として保持する。

### 5.2 Labの取得・実行

| ID | 要件 | 優先度 |
| --- | --- | --- |
| LAB-01 | レビュー済みのVulhubまたは互換LabをLessonへ紐付けられる | P0 |
| LAB-02 | Git URL、コミットSHA、対象ディレクトリ、コンテナイメージを固定して取得する | P0 |
| LAB-03 | Labの取得と起動を分離し、受講者の明示操作によって起動する | P0 |
| LAB-04 | Docker Compose設定と関連ファイルを起動前に検査する | P0 |
| LAB-05 | 公開ポートを原則としてループバックへ制限する | P0 |
| LAB-06 | 特権コンテナ、ホストネットワーク、危険なホストマウントなどを拒否する | P0 |
| LAB-07 | 起動状態、接続先、使用ポート、実行上の注意を表示する | P0 |
| LAB-08 | Labを停止・削除し、残存するコンテナ、ネットワーク、Volumeを確認できる | P0 |
| LAB-09 | 起動失敗時に原因と復旧方法を表示する | P0 |
| LAB-10 | 一定時間後にLabを自動停止する | P1 |
| LAB-11 | CPU、メモリ、ディスク、ネットワークを制限する | P1 |
| LAB-12 | 脆弱版と修正版を切り替える、または並べて比較できる | P1 |
| LAB-13 | インターネット接続を制限した隔離実行に対応する | P1 |

### 5.3 研修管理

| ID | 要件 | 優先度 |
| --- | --- | --- |
| ORG-01 | 組織ごとにユーザーと研修データを分離する | P1 |
| ORG-02 | 組織管理者、研修担当者、教材作成者、レビュー担当者、受講者の権限を設定する | P1 |
| ORG-03 | 受講者を部署、チーム、入社期などのグループで管理する | P1 |
| ORG-04 | コース、対象者、受講期限、完了条件を指定して研修を割り当てる | P1 |
| ORG-05 | 未着手、受講中、完了、要再受講の状態を確認する | P1 |
| ORG-06 | 受講者が提出した原因分析や修正方針を確認できる | P1 |
| ORG-07 | 受講結果をCSVなどで出力できる | P1 |
| ORG-08 | 教材の公開、更新、割り当て、受講完了に関する監査ログを保持する | P1 |
| ORG-09 | SAMLまたはOIDCを使ったSSOへ対応する | P2 |
| ORG-10 | 既存LMSへ受講結果を連携する | P2 |

操作ログの細かな監視を理解度の代替にしない。評価の中心は、受講者が提出した原因、影響、修正、再発防止の説明とする。

### 5.4 教材作成・レビュー

| ID | 要件 | 優先度 |
| --- | --- | --- |
| CNT-01 | 学習内容を持つLessonと実行環境を持つLabを分離して管理する | P0 |
| CNT-02 | 教材に原典、ライセンス、対象製品、対象バージョン、CVE IDを記録する | P0 |
| CNT-03 | 1つのLabへ複数のLessonを紐付けられる | P1 |
| CNT-04 | LessonとLabを独立してバージョン管理する | P1 |
| CNT-05 | 教材を下書き、レビュー中、公開、非公開の状態で管理する | P1 |
| CNT-06 | 作成者とは別の担当者による公開承認を要求できる | P1 |
| CNT-07 | 変更時に再レビューが必要か判定できる | P1 |
| CNT-08 | 企業独自の教材や社内事例を非公開で登録できる | P2 |

## 6. AIによるCVE取り込み支援

AI取り込みは、MVPに必須の機能ではない。将来的に教材作成者の調査とLab取り込みを支援する機能として扱い、未レビューのコードや環境を自動実行する機能にはしない。

### 6.1 想定フロー

1. 教材作成者がCVE IDを入力する。
2. AIがベンダーアドバイザリ、NVD、GitHub、Vulhubなどの候補情報を調査する。
3. 影響製品、対象バージョン、原因、修正、原典を整理する。
4. 利用可能なDockerまたはCompose環境の候補を提示する。
5. 候補環境を一時領域へ取得し、設定と構成ファイルを静的検査する。
6. Reprokit Manifest、Lockfile、Lesson構成の下書きを生成する。
7. 教材作成者とセキュリティレビュー担当者が内容と安全性を確認する。
8. 承認された固定リビジョンだけをRegistryへ登録する。

### 6.2 機能要件

| ID | 要件 | 優先度 |
| --- | --- | --- |
| AI-01 | CVE IDから一次情報と信頼できる関連情報を収集する | P2 |
| AI-02 | 影響製品、対象バージョン、原因、影響、修正情報を出典付きで整理する | P2 |
| AI-03 | Vulhub、GitHubなどから再現環境の候補を提示する | P2 |
| AI-04 | 候補ごとに出典、ライセンス、最終更新、固定可能なリビジョンを記録する | P2 |
| AI-05 | 取得した構成を実行せずに静的検査する | P2 |
| AI-06 | ManifestとLockfileの下書きを生成する | P2 |
| AI-07 | 学習目標、再現手順、観察点、原因、修正説明の下書きを生成する | P2 |
| AI-08 | 情報不足、出典間の矛盾、再現環境の危険性を明示する | P2 |
| AI-09 | 人によるレビューと承認が完了するまで公開・実行を禁止する | P2 |

### 6.3 禁止事項

- AIが見つけた未レビューのコードやコンテナを自動実行する
- 可変ブランチや`latest`タグを固定せずに教材として公開する
- 第三者のシステムを対象にしたPoCを生成・実行する
- 任意の攻撃対象や任意コマンドを入力できる攻撃実行機能を提供する
- 出典が確認できない原因、影響、修正情報を公開する
- ライセンスが不明な環境や教材を再配布する

## 7. 想定アーキテクチャ

脆弱なLabを共有サーバーから直接公開しない。法人向け管理機能とLab実行機能を分離する。

```text
法人向け管理プレーン
├─ 組織・ユーザー・権限
├─ 教材・コース・割り当て
├─ 進捗・提出物・監査ログ
└─ 承認済みLabメタデータ
             │
             ▼
受講者PCまたは企業管理の隔離環境
└─ Reprokit Runner / Go Core
   ├─ 固定リビジョンのLab取得
   ├─ Manifest・Compose安全性検査
   ├─ Docker Composeライフサイクル
   └─ 停止・削除・残存リソース確認
```

管理プレーンをSaaSにするか、企業内へセルフホストするかは未決定とする。MVPでは単一組織・ローカル実行でもよいが、Lab実行と研修管理の責務は分離して設計する。

## 8. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 再現性 | 同じ教材は同じソース、イメージ、設定から再構築できる |
| 安全性 | 外部公開を既定で禁止し、危険なCompose設定を起動前に拒否する |
| 追跡可能性 | 教材の根拠、Labの出所、リビジョン、レビュー履歴を追跡できる |
| 監査性 | 教材の公開・更新、研修割り当て、完了状態の変更を記録する |
| プライバシー | 必要以上のコマンド履歴、ソースコード、秘密情報を収集しない |
| 企業環境互換性 | プロキシ、プライベートレジストリ、外部通信制限を考慮する |
| 可用性 | Lab起動失敗時に原因と復旧手順を確認できる |
| 保守性 | LessonとLabを独立して更新・廃止できる |
| アクセシビリティ | キーボード操作と読みやすい日本語教材へ対応する |

## 9. MVPの範囲

MVPでは、まず1社の研修担当者が若手開発者向け研修を実施できる状態を目指す。

### 9.1 MVPに含める

1. レビュー済みのVulhub Labを固定コミットから取得できる。
2. Labを安全性検査後に明示起動し、停止・削除できる。
3. 実在事例を「再現 → 原因 → 修正 → 再発防止」まで学べる。
4. 脆弱版と修正版を比較できる。
5. 受講者が原因と対策を回答できる。
6. 研修担当者向けの進行ガイドと回答例がある。
7. 初期2教材を使い、企業研修を模擬実施できる。

### 9.2 MVPに含めない

- SSOと複雑な組織権限管理
- 既存LMSとの連携
- 企業独自教材のセルフサービス作成
- AIによるCVE調査・Lab取り込み
- 大量の教材を収録したカタログ
- 第三者システムに対する診断・攻撃機能

## 10. MVPの成功条件

- 研修担当者が、追加の脆弱環境構築を行わずに研修を開始できる。
- 受講者が、実在事例の発生条件と影響を安全なLabで確認できる。
- 受講者が、脆弱性の原因、修正方針、再発防止を自分の言葉で説明できる。
- 研修担当者が、回答例または評価基準を用いて理解度を確認できる。
- 研修終了後に脆弱環境を停止・削除し、残存リソースを確認できる。
- 初期2教材について、企業研修としての所要時間、完走率、つまずき箇所を検証できる。

## 11. 対象外

- セキュリティ専門職全般を育成する総合教育プラットフォーム
- 全社員向けの標的型メール、情報管理、コンプライアンス研修
- CVE IDを入力して第三者環境を自動攻撃するツール
- 任意のPoCを無条件に取得・実行するツール
- 実行環境だけを提供し、原因や修正を扱わない脆弱環境カタログ
- Dockerを完全なセキュリティ境界として保証すること

## 12. 未決定事項

- 管理プレーンをSaaS、セルフホスト、または両対応のどれにするか
- 受講者端末でDockerを利用できない企業への実行環境提供方法
- 理解度評価を自動採点、担当者レビュー、両方のどれにするか
- 修正版Labを別環境として持つか、同じLab内で切り替えるか
- 法人向けMVPで最小限必要なアカウント・進捗管理の範囲
- 初期教材2本が企業の開発者研修として適切か、別の題材へ変更するか
- 研修結果の保存期間と、企業ごとのデータ保持ポリシー
